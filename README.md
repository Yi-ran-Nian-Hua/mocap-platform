# CMAvatar 动捕接收平台

本机运行的轻量网页平台，默认接口 **`MCAvatar@192.168.1.200`**。接收官方 SDK 提供的人体骨骼、刚体与标记点，支持三维预览、数值查看、录制及 JSONL / CSV 导出。基础采集仅使用 Python 标准库；MANO 皮肤拟合另需 NumPy、SciPy 和本地模型。无前端构建步骤、无 CDN。

## 启动

GitHub 源码仓库不包含厂商 DLL、MANO 模型或个人采集数据。首次克隆后，从[上游固定版本的 CMVrpn.dll](https://github.com/ChingMuVisionTech/ChingMuPythonSDKs/blob/8d4ed624f204689e29d90813466e53d512f7fc94/ChingmuDLL/CMVrpn.dll) 下载原始文件，放到 `sdk/CMVrpn.dll`；来源和校验值见 `sdk/PROVENANCE.txt`。MANO 皮肤预览另需按下文准备模型。

1. 在 Windows 64 位系统安装 Python 3.10 或更新的 64 位版本。
2. 双击 `start.bat`，浏览器打开 `http://127.0.0.1:8765`。
3. 确保本机可访问发送主机，CMAvatar 已启用 VRPN 数据输出。
4. 保持设备名 `MCAvatar`、主机 `192.168.1.200`、端口 `3883`，点击连接。
5. 按 CMAvatar 的人物 ID 调整人体 ID 范围。默认 `0–15`，最多同时检查 64 个 ID。刚体和标记点不依赖这份人物 ID 列表。

也可以在该目录运行 `python server.py --open`。端口冲突时运行 `python server.py --port 8766 --open`。在启动窗口按 Ctrl+C 停止服务。

## 查看与录制

- 接收线程与页面刷新独立；可见的实时空间预览目标为每秒 60 次，实际受取数、绘制耗时和浏览器调度影响。数值表只在可见时每 250 毫秒更新，并复用已有单元格。预览移出屏幕或冻结时，普通取数降至每秒 4 次；后台页降至每秒 1 次；标定采集期间保留至少每秒 20 次的取数目标。屏幕外和冻结的预览不重复绘制，请求串行执行，不堆积旧帧。
- 左键拖动三维视图旋转，Shift＋左键拖动或右键拖动平移，滚轮缩放；适配视图按钮重新取景并重置平移。
- 取消勾选“显示刚体”可隐藏刚体点及 RGB 坐标轴，适配视图也会排除这些点；数值表、接收和录制仍保留刚体数据。
- 点击“冻结帧”固定当前三维画面与数值表，仍可旋转、平移、缩放。后台接收和录制继续运行；点击“恢复实时”切回最新数据。
- 按本发送端的 ID 规则，Tracker ID 小于 300 为刚体，ID 从 300 起为骨骼关节。骨骼关节不会重复计入刚体或绘制刚体坐标轴；已有骨骼关节流时，三维图不再重复绘制骨骼轮询坐标。
- “骨骼显示”可选择关节流或源骨骼。自动模式优先显示仍在更新的关节流，关节流过期时回退到新的源骨骼；每次只显示一种来源，数值表与录制始终保留全部数据。
- 骨骼使用 SDK 提供且模式匹配的层级。手部关节流按同模型、同左右侧的关节名称修正显示连线：手腕连接各指第一节，每指随后按 1–4 节连接；缺失或歧义名称不推测连接。原始层级及录制数据不变。没有层级信息时显示关节点。源骨骼使用全局位置；重定向骨骼保留原始数据，位置空间标为 unknown，不把未核实的坐标误画为全局坐标。
- 点击开始录制，结束后点击停止。文件保存在本目录的 `recordings/`；历史文件提供 JSONL、CSV 下载。
- JSONL 保存完整事件，包括配置、接收时间、源帧信息（SDK 提供时）、层级、位置和四元数。CSV 将刚体、每个关节与每个标记点展开为行，四元数顺序为 `x,y,z,w`。
- 开始录制会保存已有样本快照（`snapshot: true`），保留原采样时间，不将它们当作新到达的数据。这也让一直静止的标记点进入录制。
- 新录制格式版本为 2，骨骼关节事件类型为 `skeleton_joint`，刚体为 `rigid_body`。此前的历史 JSONL 文件原样保留，不重写其中的旧类型标签。
- 数值保持 SDK 原始坐标轴和单位，不擅自转换为米或毫米。不同类型数据并非已经时间同步的统一帧。
- 断开连接会自动结束录制，避免不同会话混入一个文件。下载前必须停止录制。

## 个人手型标定（MANO 数据准备）

标定单位为毫米。先输入采集人档案名称，在张手状态冻结画面，逐个确认黄色 Marker ID 对应的左右手和部位；手指 1–4 表示从近手掌端到指尖。不要把蓝色流中与 Marker ID 重复的点当成骨骼关节。程序只将有明确手部名称的源关节加入标定样本。

分别采集张手、并指、弯指姿态。每段约 2 秒，保留多帧原始点位以及各自时间信息；页面会提示连接中断、点位丢失等情况。可选填写左右手的手长、掌宽、掌厚和标记球半径，所有数值均为实际测量值，未测量的项目留空。档案保存在 `recordings/calibrations/`，可重新加载或导出 JSON。已有姿态样本时对应关系会锁定；要重新分配点位，先删除草稿中的全部姿态样本，已保存文件不受影响。

保存的是**待拟合的个人标定数据**。本机已准备左右手模型，位于 `models/mano/`，原始 PKL 和经过数值一致性验证的 NPZ 均保留，详情见该目录的 `manifest.json`。NPZ 使用 NumPy 的 `allow_pickle=False` 读取。模型文件不随应用 ZIP 分发，其他机器需从 https://mano.is.tue.mpg.de/ 按许可取得并准备同格式 NPZ。

## 实时 MANO 手部皮肤

在“个人手部蒙皮”选择已保存的三姿态档案，点击“拟合手型并启动”。左右手分别估计手型，骨骼与标记点两种方法共用该手型；蓝色由骨骼位置驱动，黄色由标记点独立驱动。切换“驱动显示”可单独观察或同时比较。皮肤支持独立冻结、旋转、平移、缩放；“暂停姿态求解”不会停止原始动捕接收。重启服务后载入最近拟合档案，点击恢复姿态求解即可继续。

本机 `start.bat` 优先使用 `../../work/mano-env/Scripts/python.exe`，已验证 Python 3.11.4、NumPy 1.23.5、SciPy 1.13.1。其他机器可在 Python 3.11 环境安装 `numpy==1.23.5 scipy==1.13.1` 后运行 `python server.py --open`；缺少数值依赖或模型时会显示具体原因，基础采集仍可使用。

- 当前档案采用标记球直径 5.3 mm、底座厚度 1 mm，球心到皮肤偏移为 3.65 mm。界面尺寸栏填写的是**半径 2.65 mm**。沿模型表面估计法线施加偏移；贴点对应的表面位置仍由标定估计。
- 稀疏点位不能唯一确定掌厚、指粗或完整皮肤表面。当前是近似个人手型，未经扫描验证。姿态使用有界 MANO PCA 约束，减少只拟合点位置导致的指节扭转。
- 四路求解在独立进程中运行，只取最新样本。缺点、过期或断连会明确标记无效，不把上一帧冒充当前结果。显示开关只影响绘制。
- “导出当前模型与指尖 JSON”包括毫米制网格、左右手各自拓扑、五个指尖表面模型点、手型参数、源时间及拟合诊断，保存的拟合档案位于 `recordings/hand_fits/`。冻结只固定画面，导出始终取后台当前结果。
- 拟合残差是输入点与模型预测点的差异，**不是指尖皮肤到物体的真实距离误差**。目前没有物体表面模型或真实接触参考，尚不计算该距离；后续需将物体表面配准到同一动捕坐标系，再计算表面距离并用独立参考验证。导出的指尖点是模型表面代表点，不等同于指腹接触点。

标记点时间表示内容最后变化时间，不是同步相机帧时间；静止点与缓存无法仅凭该接口区分。档案会保留这一限制，不能直接用于宣称严格同步的准确度结果。

## 数据状态与限制

- TCP 端口可达不代表有动捕数据；页面根据近期数据更新显示接收状态，超过 2 秒的对象标记为过期。
- 官方 SDK 没有人物 ID 枚举接口，ID 不在配置范围内的人体不会被轮询；需按发送端设置调整。
- 骨骼与标记点接口读取 SDK 最新缓存，采样频率默认 120 Hz，可调 1–240 Hz。这是监控与采样录制工具，**不保证逐帧无丢失**。高频同步、离线精确重建应使用发送端原生录制。
- 标记点接口没有源帧号或时间戳。本工具在标记点内容改变时记录，静止与断流不能仅凭该接口区分；因此静止标记点可能显示过期。骨骼按帧信息及内容变化记录。
- “事件/秒”不是摄像机帧率；一个源帧可能包含多个对象事件。队列溢出会显示丢弃计数，不会静默声称完整录制。
- SDK 在独立进程中运行。DLL 错误不会直接结束网页服务；异常信息显示后可重新连接。
- 接收进程按最多 128 条或约 5 毫秒小批量传输，保留各条原始时间戳；队列丢弃计数按事件数统计。录制每批刷新磁盘，停止时排空可正常送达的队列；仍不承诺逐帧无损。
- 页面仅监听 `127.0.0.1`，录制数据留在本机，不上传云端。

## SDK 来源

官方仓库：https://github.com/ChingMuVisionTech/ChingMuPythonSDKs

接入依据为官方 `Demo/get_human_data.py`、`get_body_data.py`、`get_marker_data.py`、`get_hierarchy.py` 和 `callback_data.py`。DLL 位于 `sdk/CMVrpn.dll`；版权归原权利人所有。仓库未提供 LICENSE 文件，本项目不为原厂 SDK 附加开源许可。原厂 README 测试环境为 Windows 10 / Python 3.10.5 / CMAvatar 1.1.0.1744。

若 DLL 加载失败，请检查 Python 与 DLL 均为 64 位、文件是否完整，以及原厂 SDK 所需的 Microsoft Visual C++ 运行库。请勿从不明站点下载替代 DLL。
